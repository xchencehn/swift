# 界面变更流程

以[产品规范](PRODUCT_SPEC.md)定义行为，以[架构](ARCHITECTURE.md)和[共享运行时约束](SHARED_RUNTIME_ARCHITECTURE.md)确定状态与性能边界。

## 定义行为

先描述使用场景、受影响用户、入口和完成条件，覆盖等待、失败、取消、重试、离线、目标变化与恢复。草稿、阅读位置、选择和展示模式属于窗口，不能借界面变更改变运行时归属。

## 实现

复用现有控件、字体、主题、间距和反馈方式。标签清晰、键盘和触摸可操作，焦点有可见位置。动画可中断、跟随明确操作并遵守减少动态效果偏好；不能阻塞已经就绪的输入。

昂贵内容按需读取，隐藏页面停止绘制和非必要工作。错误留在具体操作附近，保留可恢复的编辑内容，避免自动重复提交。

## 验证

使用隔离的合成数据验证正常、错误和恢复流程。保存桌面、平板与窄屏截图，并核对实际几何、溢出、主题、字号、键盘和草稿。界面依赖原生能力时补充真实运行时或客户端验证，不以截图代替。

工程记录说明改了什么、为何修改、如何验证和仍未覆盖的环境。仓库文档只保留当前行为与长期约束，阶段实验和个人部署记录不放入产品规范。
